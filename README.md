# 机场地面保障调度管理系统

面向航班机位分配、廊桥调度、行李转运、货物装卸、航空加油、航食配餐与客舱清洁全流程的机场地面保障调度管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-handling:entries` 这一项，或调用 `resetModule(模块)`。

## 应急保障链路

应急保障按「应急编号 → 事件类型 → 响应等级 → 处置措施」登记，状态只能沿登记的顺序
向前走一步，跨级、回退、重复操作都会被拒绝（`src/data/audit.ts` 的 `canRunAction`）：

```text
登记（应急编号/事件类型/涉及航班/事发位置/响应等级/响应人员/处置措施）
        │
        ▼
┌──────────┐  启动响应   ┌──────────┐  落实处置   ┌──────────┐  解除应急   ┌──────────┐
│  待响应   │ ─────────▶ │  响应中   │ ─────────▶ │  处置中   │ ─────────▶ │  已解除   │
│ 待处理    │            │ 待处理    │            │ 未解除    │            │ 已闭环    │
└──────────┘            └──────────┘            └──────────┘            └──────────┘
  跨级/回退/重复点击：runAction 直接返回失败，状态不变，也不新增样例
```

审计标记（`isPendingRow` / `isAbnormalRow`）是业务页面与「运营概览」共用的唯一口径：
只有末状态「已解除」算闭环，待响应/响应中/处置中都标「未解除」计入待处理，
异常记录优先标「异常」；未解除记录绝不会被当成已完成展示。

## 构建、部署与本地数据加载

```text
npm install / npm run build ──▶ vue-tsc 类型检查 + vite 打包到 dist（纯静态文件）
        │
        ├─ 开发：npm run dev，监听 127.0.0.1:5173（不自动开浏览器，无 /api 代理）
        ├─ 容器：Dockerfile 跑 dev --host 0.0.0.0，docker-compose 映射 5173
        └─ 运行时首次打开页面：
               读 localStorage 分模块键 airport-ground-handling:entries:<模块key>
                 ├─ 键存在（断点）：直接读该模块，只做一次兼容迁移
                 ├─ 键损坏：隔离到 <键>.corrupt.<时间戳>，该模块退回示例数据
                 └─ 键不存在：读老版本整包键，没有则播种示例；逐模块写断点
               迁移只补缺字段、按状态重算 pending，不改写任何状态含义；
               同一业务主键的记录自动去重，重复上线/重复加载不产生重复样例；
               全部模块落好断点后才清理老整包键——中途失败下次从断点继续。
```
